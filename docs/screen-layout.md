## 3. 사용자 제안 배치 (2026-05-16)

> "춤추는 알바트로스 들어가는 영역은 블록영역 바깥의 중앙 최상단으로 해주고. 스테이지 이동 조작하는 바가 하단 빈 영역에 들어가게 해줘."

### 3-1. Cheer Mascot 이동: 우하단 → 상단 중앙

| 항목 | 현재 | 제안 |
|---|---|---|
| 위치 | (920, 1750) 우하단 | **(540, 300) 중앙 최상단** — 블록 영역 바깥 |
| 크기 | 110×110 | 200~250px 정도 키울 수 있음 (공간 여유) |
| HUD 와의 관계 | 무관 | 위 HUD 의 y=200 빈 공간 활용. SCORE/HIGH SCORE/ROUND 의 *아래쪽* 에 배치 |
| 시각 의도 | 응원 캐릭터 (작게) | 캐릭터를 메인 비주얼로 강조. 모바일 세로 화면 상단에 시선 집중 |

### 3-2. Bar(게임 조작용) 이동: 플레이필드 안 → 캔버스 하단 빈 영역

| 항목 | 현재 | 제안 |
|---|---|---|
| 위치 | 플레이필드 (360, 660) — 플레이필드 안 | **캔버스 하단 빈 영역** (예: y=1500~1700) |
| 의미 | 플레이필드 좌표계 안에서 좌우 이동 | 캔버스 좌표계 — 터치 친화적 영역에서 좌우 이동 |
| 충돌 | playfield 안에서 공과 충돌 | 그대로 — 충돌 판정은 *논리상* 플레이필드 안의 가상 위치에 매핑? **결정 필요**. |

**Open question (Bar 이동 디테일):**
- (i) 시각만 하단으로 이동, 충돌은 여전히 플레이필드 안 (y=660 위치): 시각과 충돌이 분리 → 좌표 컨벤션 드리프트 위험 (오늘 잡은 버그 재발). 비추.
- (ii) Bar 가 캔버스 좌표계로 이동하면서 공도 캔버스 좌표계로 변환: 플레이필드 좌표계 전면 재설계. 큼.
- (iii) 플레이필드 자체를 캔버스 하단까지 늘림 (playfield 720×900 같은 비율 변경): 블록 영역은 그대로 두고 아래 빈 영역만 추가. 가장 자연스러움 — 단 stage JSON 의 barSpawnY 등 조정 필요.
- **권장:** (iii). 플레이필드 height 만 키우면 됨 (예: 720 → 900). 블록 그리드는 위쪽에 고정, 바는 늘어난 아래 영역에 배치.

### 3-3. 모바일 대응 의도

세로 모바일 화면 (예: iPhone 19.5:9 = 1080×2356 — 19.5:9 표준):
- 1080×1920 베이스 → 19.5:9 기기는 위/아래 letterbox 또는 추가 영역
- 사용자가 손가락으로 닿기 쉬운 영역은 **화면 하단** (자연스러운 엄지 위치)
- 현재 바가 플레이필드 한가운데 (캔버스 y=1260 부근) 에 있으면 한 손 조작 어색
- **하단 빈 영역으로 바 이동 = 모바일 한 손 엄지 조작 친화**

## 4. 에디터화 — 어떤 영역을 데이터로 노출?

현재 코드 const 로 하드코딩되어 있는 값들을 **stage 데이터 또는 글로벌 layout 데이터**로 빼서 에디터로 조정 가능하게.

### 4-1. 글로벌 (모든 스테이지 공통) — 새 파일 `LayoutConfig`

| 필드 | 현재 const | 의미 |
|---|---|---|
| `canvasWidth` | 1080 | 캔버스 가로 |
| `canvasHeight` | 1920 | 캔버스 세로 |
| `playfieldOffsetX` | 180 | 플레이필드 좌상단 x |
| `playfieldOffsetY` | 600 | 플레이필드 좌상단 y |
| `playfieldWidth` | 720 | 플레이필드 가로 |
| `playfieldHeight` | 720 | 플레이필드 세로 |
| `hudRegion` | y=0..200 영역 | SCORE/HIGH SCORE/ROUND 행 |
| `mascotRegion` | (현재 우하단) | 중앙 최상단으로 이동 — 위치/크기 |
| `livesBarRegion` | (현재 좌하단) | 위치/크기 |
| `barTrayRegion` | (제안 — 하단 빈 영역) | bar 가 위치할 캔버스 영역. 옵션 (iii) 적용 시 사용 |

위 값들은 `LayoutConfigTable.ts` 같은 데이터로 빼고, 에디터에 *전용 탭* 추가해서 시각적으로 영역 드래그 조정 가능하게.

### 4-2. 스테이지별 — `StageDefinition` 에 추가 가능

| 필드 | 현재 | 의미 |
|---|---|---|
| `barSpawnX` | 360 | 바 spawn x (플레이필드 좌표) |
| `barSpawnY` | 660 | 바 spawn y (플레이필드 좌표) |
| `ballSpawnX` | 360 | 공 spawn x |
| `ballSpawnY` | 600 | 공 spawn y |

이미 stage JSON 에 들어있음. 그대로 유지.

옵션 (iii) 채택 시 playfieldHeight 가 늘어나면 barSpawnY 도 자동 조정 (예: playfield 의 하단 30px 위).

### 4-3. 에디터 UI 변경

에디터에 새 모드/탭 추가:
- **Layout 탭** — 글로벌 캔버스 영역 시각 조정 (드래그로 mascot/bar tray 영역 위치/크기). LayoutConfigTable 한 곳 수정 → 모든 스테이지에 반영.
- **현재 Stage 탭** (이미 있음) — 블록/스피너/border/door 배치는 그대로.

## 5. 권장 진행 단계 (leaf-first)

각 단계가 독립적으로 검증 가능:

```
1. LayoutConfig 타입 + 기본 테이블 작성 (현재 const 값 그대로 옮김)
   → 동작 변경 없음. 데이터 위치만 이동.

2. renderInGameScreen.ts 가 const 대신 LayoutConfig 읽도록 변경
   → 여전히 동작 변경 없음.

3. Cheer mascot 위치 → 중앙 최상단 (LayoutConfig 만 수정)
   → 시각 확인.

4. 옵션 (iii) — playfield height 늘리기 + bar tray 영역 정의
   → barSpawnY 조정, 블록 그리드는 위에 고정.

5. (선택) 에디터에 Layout 탭 추가 — 드래그 조정 UI
   → 단순 const 수정으로 끝나면 이 단계는 미룰 수 있음.
```
